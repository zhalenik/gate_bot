# Правила разработки

Начать с `APP_DESCRIPTION.md`, затем `docs/ARCHITECTURE.md`, `docs/ROADMAP.md` и актуального кода. `docs/archive/` — исторические намерения, не активное техническое задание.

## Обязательные инварианты

- YCLIENTS только GET по allowlist. Даже «тестовая» отправка SMS, логин POST или перенастройка webhook не разрешены.
- У каждого клиентского и административного действия есть точный филиал; fallback на чужой филиал запрещён.
- Web, Telegram и MAX открывают ворота только через `AccessService`.
- Ручная блокировка выше CRM. Отказ от уведомлений не отзывает доступ.
- Перед привязкой номера проверить принадлежность контакта. Номер из текста не является доказательством.
- Не создавать реальные звонки/сообщения из тестов, импортов, CI или диагностических скриптов.
- Секреты и operational data находятся вне Git. Проверять exact tracked set и историю перед публикацией.

## Работа с изменениями

Новые изменения делать в тематической ветке; использовать PR с описанием проблемы, изменённого поведения и проверок. Небольшие связные коммиты. Сначала воспроизводимый дефект/сценарий, затем решение. Изменение бизнес-правила отражать в документации и regression test.

Для API использовать официальные документы и зафиксированную дату проверки. Для MAX читать `docs/MAX.md` и официальный MAX Agent Skill, не переносить формат Telegram. Логи должны помогать отличить отсутствие права, очередь, timeout и отказ провайдера, не раскрывая payload/credentials.

## Проверки перед merge

```text
python -m pip install -r requirements-dev.txt
python -m pytest -q
python scripts/scan_public_tree.py
python -m compileall -q .
```

JS после изменения: `node --check static/js/admin.js`. Изолированные тесты получают временный data directory. Истинную проверку железа обозначать отдельно от fake serial tests.

Основная ветка содержит очередную тестовую сборку. Коммерческий production/stable не обновляется самим фактом merge. Для первого baseline deployment ещё не выполнен; версии следует считать alpha до завершения соответствующих пунктов ROADMAP.
