# Email через SMTP

Настройка общая для установки и доступна только суперадминистратору: меню аккаунта → **Отправка email**, адрес `/admin/smtp`. Администраторы филиалов выбирают свои каналы уведомлений, но не получают параметры или пароль почтового сервера.

1. Укажите SMTP-сервер почтового провайдера, режим SSL/TLS (обычно 465) или STARTTLS (обычно 587), логин и пароль приложения.
2. Укажите имя и email отправителя. Провайдер должен разрешать отправку с этого адреса; логин и адрес отправителя могут отличаться.
3. Нажмите **Проверить соединение**. Текущие поля сохранятся, затем GateBot проверит TLS, авторизацию и ответ сервера. Письмо при этой проверке не отправляется.
4. Включите **Отправлять email** и сохраните. Изменения подхватываются следующей отправкой без перезапуска. Общий выключатель `OUTBOUND_ENABLED` также должен разрешать исходящие уведомления.

Пароль не возвращается в браузер. Пустое поле сохраняет прежний пароль; для удаления есть отдельный флажок. Для включённого сервера с авторизацией нужны одновременно логин и пароль. Незашифрованное соединение не поддерживается, проверка сертификата TLS не отключается.

До первого сохранения используются прежние настройки `.env`: `SMTP_ENABLED`, `MAILING_SMTP_SERVER`, `MAILING_SMTP_PORT`, `MAILING_SMTP_USER`, `MAILING_SMTP_PASSWORD`, `MAILING_SMTP_FROM`. Дополнительно доступны `MAILING_SMTP_SECURITY=ssl|starttls` и `MAILING_SMTP_FROM_EMAIL`; если последний пуст, email отправителя берётся из логина. Веб-форма не меняет `.env`.

После сохранения настройки находятся в зашифрованной записи `application_settings.smtp` общей SQLite. В резервную копию нужны БД и `data/integration.key`; без ключа сохранённые параметры нельзя прочитать. В публичный Git, диагностические события и ответы API пароль не попадает.

Проверки разработки офлайн: SMTP-соединения подменены, письма не отправлялись. Успешная проверка соединения не гарантирует доставку конкретного письма: ограничения адреса отправителя, лимиты провайдера и фильтры получателя применяются отдельно.
