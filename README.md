# GateBot

Управление доступом на парковку самостоятельных филиалов и компаний с YCLIENTS: веб-интерфейс, QR ворот, Telegram/MAX и GSM-модуль SIM800C.

**Текущая версия: `0.2.0-alpha.11`, 18.11.2026, сборка для локальной приёмки.** Согласованы роли администраторов и клиентские карточки, защищён последний администратор, добавлены удаление филиала супером, настройки каналов клиента из таблицы и недельное расписание доступа. Сохранены два способа подключения YCLIENTS, системные настройки, роли и приглашения, email-регистрация и SMS-восстановление, помощь и поддержка, [редактор цветов](docs/PALETTE.md), подписки и статистика. Trial — два календарных месяца без квоты. Известные записи YCLIENTS активируются локальным таймером до двухчасового срока. Данные приложения хранятся в SQLite; журнал звонков и SMS остаётся приватным JSON. Результаты офлайн-проверок и Chrome — [ACCEPTANCE](docs/ACCEPTANCE.md). Внешние подключения, доставка и production принимаются отдельно.

Новое в `alpha.11`: [YCLIENTS ID по телефону](docs/YCLIENTS_CLIENT_IDS.md) заполняется фоновым поиском после создания клиента в филиале CRM. В карточке доступно «Обновить ID из YCLIENTS», в интеграциях — «Обновить ID всех клиентов». Планировщик сопоставляет существующие обычные карточки, сохраняя их ссылки, роли, ручные права и настройки. Неоднозначные совпадения остаются для ручной проверки; гости сохраняют отдельные разовые пропуска. Поиск читает клиентскую базу через официальный устаревший GET, требует прав на полный телефон и не меняет CRM.

Новое в `alpha.10`: в «Интеграциях» можно отправить тестовое сообщение через ChatPush по телефону или клиенту филиала, а через YCLIENTS — клиенту с ID CRM. Провайдер теста выбирается отдельно от автоматической рассылки. [Получатели, ограничения и результаты](docs/MESSENGER_DELIVERY.md).

## Быстрый запуск на Windows

**Для Cursor и готового приватного пакета с реальными токенами:**
[пошаговая инструкция CURSOR_WINDOWS.md](docs/CURSOR_WINDOWS.md).
В этом случае используйте существующие `.env` и приватное состояние `data/`, без создания демо
и без копирования `.env.example` поверх готового файла. После SQL-миграции прежние JSON — резервные исходники, настройки меняются через приложение.

Нужен Python 3.12 или 3.13. Команды выполняются в PowerShell в каталоге репозитория.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe manage.py init-demo
$gatebotOwnerPhone = Read-Host "Телефон суперадминистратора с кодом страны"
.\.venv\Scripts\python.exe admin.py --username owner --name "Суперадминистратор" --super --phone $gatebotOwnerPhone
.\.venv\Scripts\python.exe run.py
```

Пароль администратора вводится в терминале; он не появляется в команде или исходниках. Интерфейс: `http://127.0.0.1:5000/admin/login`. Команда `init-demo` выводит персональную ссылку демонстрационного клиента. Демо использует вымышленные номера и `GATE_DRY_RUN=true`.

Не выполняйте `Copy-Item` поверх уже заполненного `.env`. Для проверки реальных ботов добавьте их токены локально и включайте по одному согласно [инструкции](docs/WINDOWS.md).

## Основные ограничения и гарантии

- Чтение YCLIENTS ограничено разрешёнными `GET`: синхронизация не изменяет записи, клиентов или настройки CRM. Авторизация, установка приложения и запрошенная рассылка через YCLIENTS реализованы отдельными потоками; они не расширяют права reader. Разработка и тесты не выполняют реальные изменения или отправки через CRM.
- Филиал — граница доступа. Обычный администратор управляет только своим филиалом. Одинаковый `client_id` в разных филиалах не объединяется.
- Веб, Telegram и MAX проверяют один общий `AccessService`. Номер ворот не принимается от клиента.
- Подтверждение телефона: собственный контакт Telegram; подписанный контакт MAX; либо персональная ссылка. Ручной ввод номера не является авторизацией.
- Ответ о принятии команды не доказывает физическое открытие: датчика положения ворот в проекте нет.
- Один процесс `run.py` владеет планировщиком, polling и COM-портом. Горизонтальное масштабирование этой сборки не поддерживается.
- «Учётная запись YCLIENTS» использует вход обычного пользователя и зашифрованный токен конкретного филиала. «Приложение YCLIENTS Marketplace» использует установку системного пользователя; ручная форма входа у такого филиала недоступна. Общие `YC_USER_TOKEN` и `YC_COMPANY_ID` больше не используются. Реальная установка по умолчанию выключена; публикация и webhooks записей остаются отдельной приёмкой.
- ChatPush подключается одним токеном. Администратор выбирает отправку через ChatPush по телефону или сервис YCLIENTS по CRM ID; автоматический выбор предпочитает подключённый ChatPush. Клиент управляет каналами Email, Telegram Bot, MAX Bot и «Мессенджеры»; отдельной клиентской SMS-рассылки нет. Гость не получает доступ к настройкам рассылки.
- Все параметры окружения доступны суперу в системных настройках; секреты не возвращаются браузеру. Изменения применяются после штатного перезапуска, SMTP — сразу. Сохранённые параметры имеют приоритет над `.env`.
- Подписки, квоты, подарки и статистика реализованы. Реальный приём платежа пока заглушка; EXOLVE и импорт сотрудников остаются будущими этапами.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/scan_public_tree.py
.\.venv\Scripts\python.exe manage.py doctor
```

Тесты используют отдельное временное состояние и запрещают внешние сетевые соединения; локальные служебные соединения `asyncio` разрешены. CI запускает их на Windows и Linux с Python 3.12/3.13. `doctor` не делает запросов к сервисам и не обращается к модему.

## Данные и секреты

`.env`, `data/`, `private/`, журналы, базы очередей, номера ворот и учётные данные не публикуются. Зашифрованные системные настройки и их ключ находятся в `private/system-config/`, независимо от каталога БД; Compose сохраняет оба каталога отдельными volumes. Резервная копия должна включать согласованные БД, ключи шифрования и системную конфигурацию. В репозитории есть только вымышленные примеры. Изменения исходных архивов не импортируются в существующую CRM и не заменяют рабочие данные автоматически. Старые TODO сохранены в `docs/archive/` как история замысла, а действующий план находится в `docs/ROADMAP.md`.
