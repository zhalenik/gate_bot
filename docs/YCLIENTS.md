# YCLIENTS: чтение и локальные права

## Неподвижное ограничение

Интеграция не имеет разрешения менять действующую CRM. В `YClientsClient.request` разрешён только `GET` по явному списку относительных путей текущего филиала. Отправка SMS, создание/редактирование/удаление записей и клиентов, вход через `POST /auth`, регистрация webhook и любые произвольные endpoints запрещены кодом.

На данный момент использованы `GET /records/{company_id}` и предусмотрено чтение `GET /client/{company_id}/{client_id}`. Чтение сотрудников внесено в allowlist для последующего этапа, но автоматический импорт сотрудников не запущен. Redirects отключены; HTTPS проверяется. Допускаются только официальные API-hosts `api.yclients.ru` и `api.yclients.com`, без credentials в URL.

## Авторизация по филиалам

Партнёрский токен поступает из `YC_PARTNER_TOKEN`. Пользовательский токен берётся из переменной, указанной в `yclients_user_token_env`, или из `YC_USER_TOKEN_<branch_id>`. Глобальный legacy fallback допустим только при точном совпадении явно заданного `YC_COMPANY_ID`; он не распространяется на произвольные компании.

Отсутствие токена для филиала вызывает локальную ошибку этого филиала. Другие филиалы продолжают синхронизацию; чужой токен автоматически не подставляется.

## Чтение снимка

Записи читаются по страницам, с проверкой типов, ID записей, повторов, company_id и постоянства `total_count`. Неполная или противоречивая пагинация отменяет применение всего снимка филиала. HTTP/JSON/timeout ошибки отделяются от успешного пустого списка: сетевая ошибка не означает отмену всех записей.

Планировщик проверяет текущий день в часовом поясе филиала, двухчасовое окно и удалённые/no-show записи. Он изменяет только локальные пропуска. Изменение телефона клиента сбрасывает предыдущие привязки мессенджеров; отсутствующее поле ответа не затирает известные контакты.

## Webhooks

Старый `webhook_handler.py` был закомментирован, а публичный endpoint сохранял произвольные headers/body без аутентификации. Эта цепочка исключена из runtime. Пока endpoint возвращает явный `503`, события webhooks не считаются обработанными и не дают права проезда.

Будущее восстановление требует подтверждённого контракта аутентификации источника, защиты от повторов и очереди. Даже после этого webhook будет поводом прочитать запись через разрешённый API, а не доверенным разрешением открыть ворота. Ни настройка webhook, ни изменение приложения в YCLIENTS не выполняются автоматически.

## Источники

Проверены 04.11.2026 (UTC):

- Официальный API: https://developers.yclients.com/ru/ — авторизация, записи, `page`, `count`, `total_count`, `with_deleted`, формат времени и значения attendance.
- Официальное описание webhooks: https://support.yclients.ru/993 — структура событий; это справочник для следующего этапа, не разрешение менять CRM.

## Проверка

`tests/test_yclients_readonly.py` проверяет запрет любых write methods, разрешённые host/path, отсутствие redirects и все ошибки пагинации. `tests/test_scheduler.py` проверяет самостоятельность филиалов, приоритет ручных прав, отписку, неуспешные снимки и временные границы. Все HTTP-ответы в этих тестах искусственные; действующая CRM не используется.
