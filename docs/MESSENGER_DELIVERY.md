# Сообщения через сервис филиала

В «Интеграциях» администратор выбирает способ отправки для своего филиала:

| Настройка | Получатель | Условия |
|---|---|---|
| Автоматически | Клиент текущего филиала | YCLIENTS по ID, затем ChatPush по телефону, затем разрешённые СМС по телефону |
| ChatPush напрямую | Телефон клиента | Токен аккаунта ChatPush сохранён в интеграции филиала |
| Сервис рассылки в YCLIENTS | ID клиента в конкретном филиале | Действующее подключение YCLIENTS, права на рассылку и настроенный там провайдер |
| СМС филиала | Телефон клиента | Филиал разрешил платные СМС и располагает квотой |

В списке доступны автоматический выбор и подключённые способы. Сохранение не отправляет сообщение.

Клиент видит один канал **«Мессенджеры (сообщение от администратора)»**. Его согласие
и `mailing_enabled` обязательны для автоматических сообщений. Старое явное согласие
на ChatPush переносится в этот канал; старый клиентский SMS-канал не переносится.
Telegram Bot, MAX Bot и Email остаются независимыми каналами.

## Тестовое сообщение из интеграций

В «Интеграциях» есть отдельная форма «Тестовое сообщение». Обычный администратор
работает со своим основным филиалом, суперадминистратор сначала выбирает филиал.
Выбор сервиса для теста не меняет сохранённый способ автоматической рассылки.

| Сервис теста | Выбор получателя |
|---|---|
| ChatPush | Ввести телефон вручную или выбрать клиента текущего филиала |
| YCLIENTS | Выбрать клиента текущего филиала с положительным ID YCLIENTS; ручного ввода телефона или CRM ID нет |

Напишите текст и нажмите «Отправить тестовое сообщение». Это явная отправка одному получателю,
а не включение автоматических уведомлений: настройки каналов, согласие на
рассылку и состояние пропуска не меняются. Текст можно редактировать; пределы —
3500 символов для ChatPush и 16000 для YCLIENTS. Кнопка недоступна, пока нет
нужного подключения или отправка выключена системными параметрами.

Используется сохранённый токен ChatPush либо credentials YCLIENTS этого филиала.
`CLIENT_OUTBOUND_ENABLED` управляет клиентской доставкой. YCLIENTS также требует
`YCLIENTS_ENABLED`. При `frozen` или `uninstalled` установка YCLIENTS не используется
для отправки. Тест не переключается на другой сервис при отказе.

Ответ о принятии означает принятие запроса провайдером, не доставку на телефон.
При неизвестном исходе проверьте результат у получателя: автоматической повторной
отправки нет. Кнопка «Проверить результат» обращается к прежнему запросу без новой
отправки. Повтор HTTP-запроса с тем же ключом не создаёт новое сообщение;
изменение текста или адресата с уже использованным ключом отклоняется. Сохранение
токена, открытие формы и загрузка списка клиентов сами по себе ничего не отправляют.

Сервер заново проверяет область филиала и выбранного клиента, не доверяя CRM ID
из браузера. Ручной телефон допустим только для явного теста ChatPush; автоматические
уведомления продолжают получать адресата из серверной карточки клиента.

## Контракт YCLIENTS

Используется только `POST https://api.yclients.ru/api/v1/sms/clients/by_id/{company_id}`.
Тело содержит `client_ids` с **одним** серверным ID и `text`. Заголовок авторизации
содержит партнёрский токен и сохранённый пользовательский токен именно этого
филиала; пользовательский токен не берётся из `.env`. Успешный HTTP `2xx` с
булевым `success=true` означает принятие запроса, не получение сообщения на
устройстве. Документация указывает `201`; в локальной проверке владельца сервис
вернул `202`, и сообщение поступило получателю. Этот код больше не считается
отказом. Явный `success=false` означает отказ; отсутствующий или непонятный ответ
при `2xx` даёт `unknown` без автоматического повтора. В диагностике сохраняется
HTTP-код, без сырого ответа и персональных данных.
[Официальный контракт рассылки](https://developers.yclients.com/ru/#tag/SMS-rassylka).

Это API SMS-рассылки YCLIENTS. Фактический канал, стоимость и возможности доставки
определяются провайдером и настройками филиала в YCLIENTS. GateBot не обещает,
что любой подключённый провайдер отправит сообщение именно в мессенджер.
Права системного или обычного пользователя на рассылку требуются только при
использовании этого способа; обычная синхронизация по-прежнему выполняет GET.

Номер телефона не заменяет ID клиента. Гостю без YCLIENTS ID этот транспорт не
отправляет сообщение; автоматического перехода к SIM800 или массовому endpoint
по фильтрам нет. Для явной отправки гостевой ссылки используется подключённый
ChatPush. SMS регистрации/OTP и ручная связь супера сохраняют отдельное назначение.

## Очередь и границы доступа

Для автоматических уведомлений `MessengerService` разрешает провайдер и получателя из серверной карточки клиента,
в том же филиале. Запрос браузера не определяет произвольный CRM ID или номер.
Настройку меняет администратор своего основного филиала либо суперадминистратор.
В outbox фиксируется выбранный транспорт; перед отправкой проверяются текущее
согласие, пропуск, провайдер и получатель. Устаревшая запись пропускается, а не
перенаправляется на другой канал или ID. Текст и адресат хранятся зашифрованно.

Отправка требует разрешения исходящих клиентских уведомлений. YCLIENTS-доставка также требует
`YCLIENTS_ENABLED`. До включения транспорт оставляет очередь ожидающей, не мешая
другим каналам. Один эффект выполняется однократно. Таймаут/непонятный ответ даёт
`unknown`, без слепого повтора и возможного дублирования сообщения.

`yclients_delivery.py` отделён от GET-only `YClientsClient`, имеет фиксированный
адрес и минимальное тело, проверяет TLS и запрещает redirects. Общий ограничитель
скорости разделяется с чтением CRM. Провайдерские тексты, телефоны и токены не
попадают в диагностический результат.

## Проверка

`test_messenger_delivery.py` проверяет запрос, выбор провайдера, ограничения ID,
границы филиала, согласие и очередь с подменёнными транспортами.
`test_messenger_settings_web.py` проверяет авторизацию, CSRF и форму выбора.
`test_integration_test_delivery.py` и `test_integration_test_browser.py` проверяют
явную отправку, список допустимых клиентов, ввод телефона, scope/CSRF,
защиту повторов и отображение результата с подменёнными транспортами.
Реальная CRM, рассылка и провайдер в ходе разработки не вызывались.
