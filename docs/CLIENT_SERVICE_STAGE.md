# GateBot · следующий этап клиентского сервиса

Исходная версия `0.2.0-alpha.18`, коммит `dfaa986`. Для продолжения после перерыва откройте этот файл, `APP_DESCRIPTION.md` и текущий `git status`. Галочка означает, что изменение работает через обычный пользовательский вход и прошло локальную проверку. Рабочие данные не нужны для тестов.

## Задачи и приёмка

- [x] Уведомлять клиента только о предоставлении доступа. Запрет, отзыв и истечение проходят тихо во всех каналах, включая ранее поставленные в очередь сообщения. Для записей YCLIENTS вычислять конец услуги. Тридцать минут спустя выдавать положенный пропуск до конца суток без рассылки. При неизвестной длительности отсечка через час от начала записи. Учесть несколько записей и опоздание очереди отправки.
- [x] В клиентском PWA оставить одну навигацию к уведомлениям, закрепить нижнее меню и учесть безопасную область экрана. Вне приложения оставить браузерные действия доступными. Заменить заголовок ошибки на «Доступ невозможен». Проверить текст редиректа.
- [x] Консольный владелец сервиса существует самостоятельно. При создании запросить логин и пароль. Обеспечить настройки собственных каналов и уведомлений без клиентской карточки. Старый пароль, канал и имеющиеся клиентские права должны пережить обновление.
- [x] На телефоне показать клиентов карточками. Сохранить поиск, фильтры, сортировку, редактирование, права и настройки каналов. На ПК оставить таблицу.
- [x] Пробный период выдаётся один раз. Для YCLIENTS ключом служит только ID салона, для самостоятельного филиала только проверенный телефон регистрации. Повторная регистрация после удаления филиала тоже проверяется. Разделить два пространства ключей.
- [x] На ПК выровнять системные настройки по ширине страницы. Сохранение доступно без прокрутки и не перекрывает поля. Дать отдельный выбор сохранить и мягко перезапустить. Завершить приём новых команд, дождаться остановки исполнителей и освобождения портов перед новым запуском. Поддержать путь `REQUESTS_CA_BUNDLE`, экспорт серверного YAML без раскрытия секретов и прокси только для Telegram.
- [x] Постоянный QR филиала открывает регистрацию посетителя. Запросить телефон и SMS, затем проверить клиентскую базу выбранного филиала. Показать найденные данные или форму нового посетителя. Новому посетителю без совпадения выдать гостевой доступ до конца местного дня. После регистрации открыть его страницу ворот. Действующие запреты и идентичности сохранять.
- [x] Дать клиенту действие «Поделиться» в браузере, клиентском PWA и обоих ботах. Получатель пользуется ограниченным делегированным пропуском. Личные настройки и права отправителя остаются у владельца.
- [x] «Обратиться к администратору» открывает звонок и переписку. При недоступном пропуске добавить запрос доступа. Дать администратору одобрение одним действием в вебе, PWA и ботах, с проверкой филиала и идемпотентностью.
- [x] Отдельное PWA администратора филиала со своей областью, установкой и Push. Включить клиентов, разовый пропуск, добавление клиента, остатки и детализацию подписки, уведомления и их настройки, переписку и справку по этим экранам. Сервер проверяет роль и основной филиал на каждом действии.
- [x] Несколько именованных SIM800C. В системных настройках карточки модемов с портом, скоростью, оператором, проверкой связи, возможностью звонить и отправлять SMS и двумя независимыми приоритетами. Для равного приоритета чередовать, для разного предпочитать старший. При занятом устройстве или подтверждённом отказе выбирать другое. Не дублировать уже принятые вызовы и части SMS при неизвестном результате. В «Связи» выбор модема или всей истории с именами. Сохранить прежнюю конфигурацию с одним модемом и единый учёт расхода.
- [x] Вернуть вкладки в «Всё о вашем тарифе», использовать общее оформление раздела. Разрешить администрации сервиса редактировать публикуемое содержание. Расчёт квот и согласия на оплату не зависят от редактируемого описания.
- [x] На клиентских страницах разместить настраиваемую ссылку на сайт сервиса и ссылку «Пожелания и отзывы». Спросить оценку и комментарий при второй команде после первого успешного открытия, далее через каждые четыре команды, пока клиент не оставит отзыв. Повтор HTTP-запроса не считается новым действием. Отзывы доступны на отдельной закрытой странице администрации сервиса.
- [x] Проверить обновление на синтетической БД, разграничение филиалов, отсутствие внешних отправок при тестах и состав публикуемых файлов. Обновить документацию и зафиксировать проверяемую версию.

Релиз `0.2.0-alpha.19`. Результат сборки образа для каждого коммита публикуется в [Publish GateBot image to GHCR](https://github.com/zhalenik/gate_bot/actions/workflows/publish-image.yml). Сервер обновляет владелец.

## Порядок продолжения

Проверить изменения в рабочем дереве перед повторной реализацией пункта. Начинать с серверного правила и хранилища, подключать его к существующим веб-, бот- и PWA-входам. Проверять успех и конкретный пограничный случай для каждого пункта. Для телефонии использовать имитатор транспорта, для CRM только имитацию или разрешённое чтение. Не копировать приватную БД, номера, SMS, ключи, логи или `.env` в репозиторий. Отмечать выполненные пункты по мере приёмки. Проверки отправки реальных SMS, устройств и Push отделять от локальных результатов.

### Инструкция для следующей сессии

1. Сверь HEAD и `git status --short` с этим списком. Пользователь обновляет сервер самостоятельно. Работай с локальным деревом, сохраняя его незакоммиченные изменения. Временная база для тестов создаётся фикстурами pytest.
2. Для сроков уведомлений пройди путь `yclients_api.eligible_clients` → `Scheduler._minimal_records` → `LinkManager.reconcile_appointments` → очередь `ProductNotifications` → исполнитель канала. Контрольные примеры в `tests/test_client_service_stage.py` и `tests/test_appointment_timer.py`. Отдельно проверь попадание записи в очередь до отсечки с доставкой после неё.
3. Для регистрации открой `trial_identity.py`, `branch_join.py`, `gate_qr_web.py` и `tests/test_branch_join_trial.py`. Повтори сценарий удаления и новой регистрации с тем же идентификатором, затем с тем же телефоном у другого типа филиала. Убедись, что владелец по-прежнему входит через консольную учётную запись и получает свои уведомления.
4. Для клиентского интерфейса проверь обычную ссылку, установленное PWA, страницу истёкшего пропуска и удалённую ссылку. В браузерных тестах `tests/test_client_pwa_browser.py` проверь Push после установки, нижнее меню при прокрутке, форму отзыва и закрытую страницу владельца. На телефоне проверь также сортировку и кнопки в карточке клиента.
5. Для передачи гостевого доступа и переписки пройди от кнопки клиента через `branch_desk.py`, `branch_desk_web.py` и `desk_bot.py` до ответа конкретного филиала. Обязательно проверь отказ чужому администратору, повтор одобрения и отзыв исходного доступа. Проверь эти же действия в отдельном `/office/` и переход из уведомления Push.
6. Для модемов найди сохранение карточек в `modem_settings.py`, выбор исполнителя в `sim800c.py` и фильтрацию `telephony_store.py`. Проверь два занятых устройства, подтверждённый отказ, неопределённый исход после передачи части SMS, остановку очереди и единственное списание квоты.
7. Для эксплуатации проверь `tests/test_system_settings_web.py`, `tests/test_system_settings_browser.py`, `tests/test_notifications.py` и экспорт `deployment_yaml.py` через `docker compose config` на вымышленных путях. При ребуте настройки сохраняются до остановки. Права на перезапуск, YAML, отзывы и изменение правил принадлежат владельцу сервиса.
8. Перед публикацией проверь состав индекса, сканер публичного дерева и локальный поиск известных секретов без печати значений. Проверь версию образа, отправь проверенный коммит в GitHub и запиши результат сборки. Внешнюю приёмку на NAS, SIM800C и телефонах Android/iOS укажи отдельно.
