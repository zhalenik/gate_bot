# Windows: запуск и локальная приёмка

Для работы **в Cursor с готовым приватным пакетом и реальными токенами** используйте
[CURSOR_WINDOWS.md](CURSOR_WINDOWS.md). В нём отдельно описаны установка пакета,
интерпретатор, запуск по F5, CRM, COM-порт и проверка ботов. Ниже сохранён общий
путь с демонстрационными данными.

## 1. Подготовка

Используйте Python 3.12 или 3.13 для Windows и PowerShell. Если Git уже установлен:

```powershell
git clone https://github.com/zhalenik/gate_bot.git
cd gate_bot
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

При отсутствии Git можно скачать `Code → Download ZIP`, распаковать и открыть PowerShell в папке с `run.py`. Активация virtualenv не обязательна: все команды ниже вызывают его Python напрямую. Не перезаписывайте заполненный `.env` при обновлении.

## 2. Сначала полностью локальный режим

Оставьте все `*_ENABLED=false` и `GATE_DRY_RUN=true`. Создайте демонстрационные данные и администратора:

```powershell
.\.venv\Scripts\python.exe manage.py init-demo
.\.venv\Scripts\python.exe admin.py --username owner --name "Суперадминистратор" --super --phone PHONE
.\.venv\Scripts\python.exe manage.py doctor
.\.venv\Scripts\python.exe run.py
```

Замените `PHONE` своим номером с кодом страны. Пароль — не менее 12 символов; терминал запросит его дважды без отображения. Откройте `http://127.0.0.1:5000/admin/login`. Команда `init-demo` также выведет персональную клиентскую ссылку. При нажатии ворот в ней ожидается явная имитация. Никакого звонка быть не должно.

Создание администратора демонстрационного филиала:

```powershell
.\.venv\Scripts\python.exe admin.py --username branch-admin --name "Администратор" --branch 1001 --phone PHONE
```

Проверьте вход обеими ролями, настройку филиала, выдачу/отзыв, временный пропуск до конца дня, CSV и логи. Добавьте второй вымышленный филиал под суперпользователем и убедитесь, что обычный администратор его не видит.

## 3. Перенос старых данных

Оригинальные архивы сохраните отдельно. В присланном `main` отсутствуют `links.json` и `admins.json`; действующая база клиентов и аккаунтов в него не вошла. В архиве есть конфигурация двух филиалов, но её телефонные номера и ключи не включены в публичные исходники.

Приватный конфигурационный пакет содержит `.env` и `data/branches.json`. В актуальном пакете для Cursor Telegram и чтение CRM включены; конкретные флаги и недостающие параметры перечислены в `private/START_HERE.md` внутри пакета. Если используется он, **не** создавайте демо поверх него и **не** заменяйте уже рабочий `data/` без резервной копии. Никакие пароли YCLIENTS для авторизации по POST не используются.

На первом этапе не импортируйте автоматически неизвестный старый каталог `storage/`: сначала проверяются связи branch/client, дубли, даты и схема администраторов. Текущие личные ссылки можно сохранить, но это отдельная проверяемая миграция, а не копирование Python-конфига из старого проекта.

## 4. Telegram polling

Заполните в локальном `.env`:

```dotenv
BOT_ENABLED=true
BOT_MODE=polling
BOT_TOKEN=YOUR_PRIVATE_TOKEN
BOT_USERNAME=YOUR_BOT_USERNAME
GATE_DRY_RUN=true
```

Перезапустите `run.py`. Сначала проверьте переход по персональной ссылке, затем вход через собственный контакт. Ручной ввод чужого номера, пересланный контакт и ворота другого филиала должны отказываться.

Не запускайте второй polling-процесс того же бота. Если у токена уже настроен webhook рабочего сервера, приложение остановит этот polling с диагностикой. Удаление рабочего webhook автоматически не выполняется; согласуйте отдельный тестовый бот или план переключения.

## 5. MAX polling

В архиве MAX нет рабочего `.env` с токеном — он должен быть заполнен локально владельцем бота:

```dotenv
MAX_BOT_ENABLED=true
MAX_BOT_MODE=polling
MAX_BOT_TOKEN=YOUR_PRIVATE_TOKEN
MAX_BOT_USERNAME=YOUR_BOT_USERNAME
MAX_API_BASE_URL=https://platform-api2.max.ru
GATE_DRY_RUN=true
```

Актуальная документация MAX требует доверия нужному сертификату для нового API-домена. Если системное окружение его не содержит, задайте `MAX_CA_BUNDLE` на проверенный PEM-bundle из доверенного источника согласно документации платформы. `verify=False` не используется. Подробности и протокол — [MAX.md](MAX.md).

Проверьте `bot_started`/`start`, собственный контакт, неверную подпись, меню нескольких филиалов, отзыв во время открытого меню, повторную доставку callback и контакт администратора при истёкшем доступе.

## 6. YCLIENTS только чтение

Проверяются существующие токены, без входа по логину/паролю и без изменения CRM:

```dotenv
YCLIENTS_ENABLED=true
YC_PARTNER_TOKEN=YOUR_PRIVATE_PARTNER_TOKEN
SCHEDULER_ENABLED=true
```

Для проверки нужен уже сохранённый в зашифрованной SQLite токен соответствующего
филиала. Старые `YC_USER_TOKEN`, `YC_USER_TOKEN_<id>` и `yclients_user_token_env` не
используются. Если подключения ещё нет, офлайн-проверка должна сообщить об этом;
не выполняйте реальный вход ради теста. Способы подключения — учётная запись
пользователя и приложение Marketplace — описаны в [YCLIENTS.md](YCLIENTS.md).
Глобальный системный токен приложения Marketplace отличается от обычного токена
пользователя бизнеса и применяется только к подтверждённым установкам.

Сначала оставьте уведомления и реальные звонки выключенными. Сопоставьте прочитанные записи с CRM визуально. GateBot записывает изменения только в своё локальное состояние. Политика запрета POST/PUT/PATCH/DELETE действует независимо от `.env`.

## 7. Уведомления

После ручной проверки получателей включите `OUTBOUND_ENABLED=true`. Это включает автоматические уведомления в уже привязанные мессенджеры. Интерактивные ответы бота работают независимо от этого флага. ChatPush подключается одним токеном через «Подключения» и отправляет JSON `phone`/`text` на `https://api.chatpush.ru/api/v1/delivery`; дополнительные scope или QR не нужны. Сохранение токена не отправляет сообщение; реальная доставка принимается отдельно. Ошибка или неизвестный результат не маскируются успешной доставкой.

## 8. SIM800C

Нужны фактический COM-порт, скорость соединения и выделенный сеанс проверки. До него сохраняйте `GATE_DRY_RUN=true`. Порядок настройки, поведения очереди и проверки длинных SMS находится в [SIM800C.md](SIM800C.md).

Для чтения сообщений в отдельном процессе остановите `run.py`, затем:

```powershell
.\.venv\Scripts\python.exe manage.py read-sms --output .\data\private-sms-test.json
```

Файл содержит реальные SMS, не включайте его в коммиты или публичные обращения. Исходные сообщения на SIM не удаляются. Присылать для диагностики нужно только обезличенные проблемные PDU и технические события.

## 9. Завершение и диагностика

Остановите `run.py` через Ctrl+C. Runtime прекращает приём новых команд и освобождает модем. Для обращения по проблеме:

```powershell
.\.venv\Scripts\python.exe manage.py doctor
.\.venv\Scripts\python.exe manage.py support-bundle --output .\data\support-bundle.zip
```

Укажите версию/commit, время, филиал, ожидаемое и фактическое действие, канал (web/Telegram/MAX), `X-Request-ID` или `command_id`, если доступны. Предварительно просмотрите содержимое bundle. Команды диагностики не проверяют сеть и железо автоматически.
