# Цвета интерфейса

Сервисная страница **«Цвета интерфейса»** находится в меню суперадминистратора по адресу `/admin/palette`. Обычный администратор и посетитель не могут открыть редактор, прочитать его API или сохранить настройки. Изменения относятся ко всей установке GateBot, включая клиентские страницы.

## Использование

В блоке **«Клиентские страницы по умолчанию»** владелец задаёт оформление пропусков для всей установки. Общая палитра кабинета сохраняет собственные настройки. Филиал с персонализацией может переопределить фон страницы и карточки ворот, шрифт, отступы, цвета, расположение логотипа, оформление кнопок и баннер. Изменения общего оформления распространяются на филиалы, использующие общие значения. Когда право на персонализацию заканчивается, клиентские страницы показывают общий вариант. Настройки филиала сохраняются в базе.

Для иконки PWA режим «Заполнить квадрат» обрезает выступающие края по центру. «Поместить целиком» сохраняет изображение целиком и показывает выбранный фон в свободной области. Поля задаются в процентах с каждой стороны. При нулевых полях квадратное изображение доходит до края иконки. Выбранный шрифт с кириллицей загружается с сервера GateBot.

В блоке «Логотип и иконка» можно отдельно загрузить логотип шапки и иконку сервиса: PNG, JPEG, WebP или SVG. Логотип сохраняет пропорции; для иконки автоматически создаются PNG 180, 192 и 512 px для iPhone/Android. SVG должен быть самодостаточным: фигуры и локальные градиенты, без скриптов, внешних изображений, шрифтов и фильтров. Текст перед загрузкой преобразуйте в кривые. Растровые файлы очищаются от метаданных. Кнопка сброса возвращает стандартное изображение независимо от палитры.

Изображения загружаются до 5 МБ (SVG — до 512 КБ), сохраняются в приватном каталоге `branding-assets` рядом с SQLite. Публичные адреса возвращают только зарегистрированные очищенные изображения, без пользовательских путей или исходного JPEG. Для резервирования нужны и база, и этот каталог. Версии изображений имеют неизменяемые адреса; системная иконка уже установленного PWA обновляется по правилам ОС при последующих проверках манифеста.

1. Найдите цвет по группе, названию, файлу или селектору. Основные переменные темы и отдельные значения компонентов представлены раздельно: одинаковый исходный оттенок у статуса и кнопки не объединяет их настройки.
2. Откройте места применения: указаны относительный файл, строка, CSS-селектор, свойство и контекст адаптивных правил. Для общей CSS-переменной показаны её использования и цепочки наследования. Старые неподключённые стили отмечены отдельно.
3. Выберите цвет на палитре или введите HEX. Прозрачность настраивается отдельно; значения с альфа-каналом хранятся в формате `#RRGGBBAA`.
4. Предпросмотр влияет только на открытый редактор. До сохранения другие страницы и пользователи видят прежние цвета. Сброс отдельного цвета или всех цветов сначала меняет черновик; отмена возвращает сохранённое состояние.
5. Нажмите **«Сохранить»**. Новые значения используются при следующей загрузке страниц, без перезапуска приложения. Уже открытые страницы следует обновить.

Места применения показаны по исходникам CSS. В конкретном состоянии страницы более позднее или более специфичное правило может перекрыть выбранное объявление: например, тема перекрывает часть базовых стилей. Начинайте с группы «Основная палитра», если хотите изменить текущие общие цвета. Пометка «не подключены» относится к старым стилям, которые сохранены в каталоге для полноты и сейчас не влияют на страницы. Флаг активности прочих записей означает, что файл подключается, а не что каждое его правило выигрывает каскад во всех состояниях.

JSON-конфиг можно скачать для копии или загрузить в черновик. Импорт не применяет цвета ко всему сайту до сохранения. Файл содержит только идентификаторы цветов, их значения и версию каталога. Изменения из другого окна и несовместимая версия каталога не перезаписываются молча.

Если подобранные цвета сделали страницу нечитаемой, откройте `/admin/palette?defaults=1`. Этот режим показывает редактор в исходных цветах и выключает предпросмотр. Сохранённая конфигурация при открытии не меняется: её можно поправить или сбросить явно.

## Что входит в каталог

Каталог охватывает цветовые значения CSS веб-интерфейса: текст, фон, рамки, тени, градиенты, прозрачность, статусы, фокус, псевдоклассы и адаптивные правила. Цвета статусов по умолчанию сохранены; теперь супер может изменить их отдельно. Для цветовых переменных показаны объявления и явные ссылки из CSS. `currentColor` продолжает наследовать цвет текста своего элемента; отдельное фиксированное значение вместо него не подставляется, поскольку источник зависит от конкретной структуры страницы.

Растровые изображения, собственные цвета SVG-логотипов и HTML-письма не являются CSS веб-интерфейса и этим редактором не перекрашиваются. CSS, который явно задаёт SVG `fill`/`stroke`, входит в каталог. Динамический оттенок аватара и aliases сохраняют исходное поведение при сбросе; выбранный вручную цвет становится фиксированным.

## Хранение и применение

`palette_catalog.py` читает сгенерированный `resources/palette_catalog.json`. Генератор `scripts/build_palette.py` выделяет значения в `var(--gb-color-…, исходное_значение)`. Идентификаторы основаны на файле, селекторе, свойстве и позиции внутри объявления, не на самом HEX; разные значения не связываются только из-за совпадения оттенка.

Настройки хранятся в `ui_palette_settings` общей приватной `application.sqlite3`: ревизия, JSON переопределений и время сохранения. Они входят в штатную резервную копию БД; `.env` и файлы исходных стилей при сохранении не перезаписываются. Цвета не являются секретами, но пользовательскую конфигурацию не добавляют в Git.

`/ui/palette.css` публично отдаёт только разрешённые CSS-переменные и проверенные HEX-значения. Селекторы, произвольный CSS, `url()`, скрипты и неизвестные идентификаторы нельзя передать через сохранение. Ответ имеет ETag с перепроверкой кеша; редактор загружает новый stylesheet после сохранения. На каждом серверном чтении настроек редактора и мутации заново проверяется роль; POST защищён CSRF, запись — ревизией и транзакцией.

Если код перестал использовать старый идентификатор, его настройка не попадает в CSS, но сохраняется для возможного восстановления. Полный сброс удаляет также такие старые значения. Аудит содержит только тип действия, ревизию и количество цветов.

## Обновление стилей разработчиком

После изменения CSS выполните `python scripts/build_palette.py`; затем `python scripts/build_palette.py --check`. Генерация повторяема и не оборачивает уже перенесённые значения второй раз. Не заменяйте цвета в строках селекторов, URL и изображениях как обычные CSS-значения. Новые компоненты должны оставаться в каталоге вместе с точными местами применения.

Автоматические проверки используют отдельное хранилище и Chrome с синтетическими данными. Реальные CRM, SIM800, SMTP и боты для проверки палитры не требуются.
