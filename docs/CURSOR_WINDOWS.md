# Запуск GateBot в Cursor на Windows с приватной конфигурацией

Инструкция обновлена 17 ноября 2026 года. Она предназначена для запуска с настоящими
токенами и филиалами из отдельно выданного приватного пакета.
Путь с демонстрационными данными описан отдельно в [WINDOWS.md](WINDOWS.md).

## 1. Что откуда загружается

| Файл | Назначение | Попадает в Git |
|---|---|---|
| `.env` в корне проекта | Токены, режимы интеграций, адрес веба, COM-порт, SMTP | Нет |
| `data/application.sqlite3` | После миграции: филиалы, клиенты, роли, настройки, подписки и очереди | Нет |
| `data/branches.json`, `links.json`, `admins.json` | Исходники до миграции; после переключения на SQL — только копии для восстановления | Нет |
| `data/integration.key`, `data/telephony.json`, `data/branch-logos/` | Ключ шифрования, отдельный архив SMS/звонков и загруженные логотипы | Нет |
| `.vscode/settings.json` и `.vscode/launch.json` | Локальная настройка интерпретатора и запуск по F5 | Нет |
| `private/START_HERE.md` | Состав конкретного приватного пакета и известные незаполненные поля | Нет |
| `storage/config.py` | Загрузчик настроек из `.env` | Да; значений секретов в нём нет |
| `auth_variables.py` | Совместимые имена для старых импортов, получающие значения из того же загрузчика | Да; изменять его для запуска не нужно |

`.env` ищется рядом с `run.py`. Относительные каталоги данных, логов и путь к
MAX CA bundle отсчитываются от корня проекта. Переменные уже запущенного процесса
имеют приоритет над файлом. Настройки перечитываются при новом запуске программы.

## 2. Открыть проект и подготовить Python

Клонируйте репозиторий в обычную локальную папку, например `C:\Projects\gate_bot`.
В Cursor выберите **File → Open Folder** и откройте именно папку `gate_bot`, в которой
находятся `run.py`, `requirements.txt` и каталог `storage`.

Откройте **Terminal → New Terminal**. Для команд ниже выбран PowerShell. Проверьте
установленные версии Python:

```powershell
py -0p
```

Нужен Python 3.12 или 3.13. Если установлен только 3.13, замените `-3.12` следующей
команды на `-3.13`. Если `py` не найден, установите Python 3.12/3.13 с python.org
с Python Launcher, затем откройте новый терминал Cursor. Python 3.14 пока не входит
в проверенную матрицу этого проекта.

Из корня проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Активация окружения не нужна: команды вызывают его Python напрямую. Если Cursor
пытается выполнить `Activate.ps1` и PowerShell запрещает скрипт, продолжайте с
полным путём `.\.venv\Scripts\python.exe`; менять системную политику ради этого не требуется.

Нажмите **Ctrl+Shift+P → Python: Select Interpreter** и выберите
`.venv\Scripts\python.exe` внутри проекта. Если такого пункта нет, установите
расширение **Python**, затем повторите выбор. Для F5 также нужно **Python Debugger**.

Проверка выбранного окружения из терминала:

```powershell
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -m pip --version
```

Версия должна быть 3.12.x/3.13.x, а путь pip — внутри `.venv` этого проекта.

## 3. Установить приватный пакет

Распакуйте выданный `GateBot_private_config.zip` в корень свежего клона. Его `.env`
должен оказаться рядом с `run.py`, а `branches.json` — внутри `data`.
Не создавайте лишнюю вложенную папку `gate_bot\GateBot_private_config\`.

Для этого варианта **не выполняйте** `Copy-Item .env.example .env` и
`manage.py init-demo`: готовые секреты и филиалы уже находятся в пакете.
При существующем заполненном `.env` или рабочем `data` сначала сохраните их копию;
не заменяйте существующие клиентские данные пакетом первоначальной настройки.

Проверьте расположение файлов без вывода секретов:

```powershell
Test-Path .\run.py
Test-Path .\.env
Test-Path .\data\branches.json
git check-ignore -v .env data/branches.json .vscode/launch.json private/START_HERE.md
git ls-files -- .env data/branches.json
```

Первые три команды должны вернуть `True`. `check-ignore` показывает правила
исключения; последний `git ls-files` не должен вывести ничего. Не используйте
`git add -f` для этих файлов. Имя конфига должно быть `.env`, а не `.env.txt`.

Откройте `private/START_HERE.md`: там указано, какие реальные значения перенесены,
какие филиалы включены и какие данные отсутствовали в исходниках.

## 4. Режим первого реального запуска

В подготовленном пакете Telegram и чтение YCLIENTS включены. Реальные токены уже
заполнены. Первичная проверка выполняется с имитацией звонка:

```dotenv
BOT_ENABLED=true
BOT_MODE=polling
YCLIENTS_ENABLED=true
SCHEDULER_ENABLED=true
GATE_DRY_RUN=true
SIM800_ENABLED=false
OUTBOUND_ENABLED=false
```

`OUTBOUND_ENABLED=false` отключает автоматические уведомления клиентам.
Ответы бота на ваши команды при этом работают. `GATE_DRY_RUN` относится к командам
ворот: Telegram и YCLIENTS продолжают обращаться к настоящим API.

MAX включается после добавления его собственного токена; SIM800 — после выбора
реального COM-порта. Значения и флаги редактируются в `.env`, исходники Python
для этого менять не нужно.

## 5. Создать администратора и проверить конфигурацию

В свежем пакете нет пользовательского пароля для админки. Создайте свой аккаунт:

```powershell
.\.venv\Scripts\python.exe admin.py --username owner --name "Суперадминистратор" --super
.\.venv\Scripts\python.exe manage.py doctor
```

Пароль терминал запросит дважды без отображения; минимум 12 символов. Уведомление
о том, что такой администратор уже существует, не требует пересоздавать аккаунт.
**Логин для входа — `owner`.** Значение `--name` («Суперадминистратор», имя или e-mail)
является отображаемым именем. Повторная команда создания существующего аккаунта
не заменяет его пароль.

Посмотреть локальные логины и задать новый пароль существующему аккаунту:

```powershell
.\.venv\Scripts\python.exe admin.py --list
.\.venv\Scripts\python.exe admin.py --reset-password --username owner
```

Если `admins.json` уже очищен или испорчен, остановите `run.py` через Ctrl+C и выполните:

```powershell
.\.venv\Scripts\python.exe admin.py --recover --username owner --name "Суперадминистратор" --super
```

Команда сначала сохраняет исходный файл в соседнюю приватную копию
`admins.json.recovery-….bak`, затем создаёт или восстанавливает указанный аккаунт.
В исправном JSON остальные администраторы сохраняются; существующий администратор
филиала не превращается в суперадминистратора. Пустой файл не является допустимым
JSON — очищать его вручную для сброса пароля не нужно. После восстановления войдите
под `owner` с паролем, заданным именно командой `--recover`.

В `doctor` проверьте:

- `.env` обнаружен;
- есть хотя бы один администратор и один включённый филиал;
- включённым ботам соответствуют заполненные токены и режим `polling`;
- для каждого включённого филиала настроена пара credentials YCLIENTS;
- `gate_dry_run` включён до аппаратного теста;
- `checks.local_config` не содержит ошибки.

`doctor` показывает наличие параметров, а не сами ключи. Он не проверяет срок
действия токена, доступность API, webhook или подключение модема. Поэтому
`network: not_run` и `physical_modem: not_run` являются нормальным результатом.

Отдельная проверка соединения и токенов ботов:

```powershell
.\.venv\Scripts\python.exe manage.py check-bots --platform max
.\.venv\Scripts\python.exe manage.py check-bots --platform telegram
```

Эта команда читает информацию о боте и наличие webhook. Она не запускает polling,
не забирает обновления, не отправляет сообщения, не обращается к CRM и модему.
Результат `status=ok` означает успешные предварительные запросы и отсутствие webhook;
сам polling нужно проверить после `run.py` по событию `BOT_POLL_READY`.
При ошибке вывод содержит `error_code`, `http_status`, `stage` и действие для исправления.
Команда возвращает код завершения 1 при ошибке API; это ожидаемое диагностическое поведение.

## 6. Первое чтение YCLIENTS

До запуска `run.py` выполните:

```powershell
.\.venv\Scripts\python.exe manage.py sync-once
```

В результате для включённого филиала ожидается `status: success`.
Эта команда читает CRM разрешёнными GET и обновляет **локальные** пропуска GateBot,
включая сроки и отзыв; также очищает локальные истёкшие временные пропуска.
В YCLIENTS она ничего не изменяет.

Импортируются подходящие записи **на текущий день** с учётом окна до визита.
Пустой список клиентов может быть правильным результатом. Проверьте дату и время
Windows и часовой пояс филиала. Для проверки бота без подходящей записи CRM
можно выдать себе ручной пропуск через админку.

Если результат содержит `status: error`, не ориентируйтесь только на код
завершения команды. Сохраните безопасный результат и события журнала.
Проверьте точный ID филиала, user token, partner token и доступ к API. Токен для
одного филиала не назначается автоматически всем остальным. Правило запрета
записи в CRM действует независимо от конфигурации.

## 7. Запустить веб, ботов и планировщик

Штатная команда одна:

```powershell
.\.venv\Scripts\python.exe run.py
```

Терминал остаётся занят работающим приложением. Ожидаемая строка:

```text
GateBot: http://127.0.0.1:5000 | gate mode: DRY RUN
```

Откройте `http://127.0.0.1:5000/admin/login`, войдите под `owner` и заданным паролем.
На странице настроек филиала проверьте название, часовой пояс, кнопки и номера.
После штатной миграции изменения сохраняются в `data/application.sqlite3`.
Старые JSON не редактируйте как рабочую базу и не копируйте поверх существующего состояния.

Альтернатива терминалу: если файлы `.vscode` из пакета установлены и доступен
Python Debugger, откройте **Run and Debug**, выберите **GateBot: local (.env)**
и нажмите **F5**. Эта конфигурация запускает тот же `run.py` с тем же `.env`.
Одновременно запускать через F5 и вторую команду в терминале не нужно.

Для остановки нажмите **Ctrl+C** в терминале и дождитесь завершения процесса.
После изменения `.env` остановите и запустите приложение заново.

## 8. Проверить Telegram

Не запускайте второй процесс polling с тем же токеном. Если старый сервер ещё
работает, сначала завершите его экземпляр бота.

В дополнительном терминале можно наблюдать журнал:

```powershell
Get-Content .\data\logs\events.jsonl -Tail 30 -Wait
```

Успешный запуск веба не доказывает подключение бота. Дождитесь события
`BOT_POLL_READY` для Telegram и после этого отправьте `/start` своему боту.
Telegram при старте может отбросить старые накопленные updates.

В админке выдайте себе ручной пропуск в нужный филиал, затем откройте его
персональную веб-ссылку и переход в Telegram. Второй вариант — отправить боту
собственный контакт, если этот номер уже есть у клиента с доступом.
Обычный текст с номером не является подтверждением номера.

Ожидаемый результат: меню своего филиала, кнопка ворот, явный ответ об имитации
команды. После отзыва пропуска прежняя кнопка не должна дать открыть ворота.

Если у Telegram настроен webhook, polling остановится. Приложение не удаляет
старую подписку само. Это отдельное переключение после остановки старого сервера;
не публикуйте webhook URL с секретными параметрами или токен в диагностике.

## 9. Настроить SIM800C

Модем должен быть физически подключён к компьютеру, где запущен `run.py`, либо
передан ему поддерживаемым способом. COM-порт другого сервера не появится на
Windows только от указания имени в конфиге. Пока модем подключён к TrueNAS,
локальную проверку веба/ботов можно продолжать с `GATE_DRY_RUN=true`.

Подключите USB–TTL и посмотрите порты:

```powershell
.\.venv\Scripts\python.exe -m serial.tools.list_ports -v
```

Сопоставьте устройство с **Диспетчер устройств → Порты (COM и LPT)**.
Например, если обнаружен именно нужный адаптер на `COM7`, укажите:

```dotenv
SIM800_PORT=COM7
SIM800_BAUDRATE=115200
SIM800_ENABLED=true
GATE_DRY_RUN=false
```

`COM7` — пример. Скорость `115200` — текущая программная настройка, а не
восстановленный параметр вашего модема; используйте фактически настроенную скорость.
Сначала остановите приложение, внесите изменения и проверьте один осознанный звонок.
Команда в очереди или ответ модема не подтверждает физическое положение ворот.

Для отдельного чтения SMS остановите `run.py` и выполните из корня проекта:

```powershell
.\.venv\Scripts\python.exe manage.py read-sms --output .\data\private-sms-test.json
```

Нужны `SIM800_ENABLED=true` и правильный порт. **Чтение SMS обращается к настоящему
модему даже при `GATE_DRY_RUN=true`**: этот флаг имитирует звонки, а не чтение.
Команда не удаляет SMS. Проверьте `status` в результате; сам факт сохранения JSON
ещё не означает успешного чтения. Этот файл содержит частные сообщения.

## 10. MAX и автоматические уведомления

Для MAX заполните в `.env`:

```dotenv
MAX_BOT_TOKEN=YOUR_PRIVATE_TOKEN
MAX_BOT_USERNAME=YOUR_BOT_USERNAME
MAX_BOT_ENABLED=true
MAX_BOT_MODE=polling
```

Перезапустите приложение. При ошибке доверия TLS используйте проверенный CA bundle
по [MAX.md](MAX.md); отключать проверку сертификата не нужно. Наличие активной
webhook-подписки также препятствует polling. Токен Telegram не подходит MAX.

`MAX_BOT_USERNAME` — никнейм бота, например `example_bot`, а не его отображаемое
название и не полная ссылка. Предупреждение `max_username_missing` означает, что
процесс не получил это значение; оно нужно для ссылок, а не для авторизации API.
Проверьте точное имя ключа, сохранение `.env` рядом с `run.py` и перезапустите команду.
Переменная процесса с тем же именем перекрывает файл даже при пустом значении.
Убедиться в её наличии, не печатая значение, можно так:

```powershell
Test-Path Env:MAX_BOT_USERNAME
```

Если хотите использовать именно сохранённое значение из `.env`, удалите перекрытие
только из текущего терминала и заново запустите проверку:

```powershell
Remove-Item Env:MAX_BOT_USERNAME -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe manage.py check-bots --platform max
```

При успешном `/me` проверка также показывает `username_configured` и
`configured_username_matches` без вывода ника или токена. Если запуск по F5 ведёт себя
иначе, проверьте настройки `env`/`envFile` этого профиля; новый терминал не меняет
окружение уже запущенного отладчика.

Для автоматических уведомлений уже привязанным клиентам отдельно установите
`OUTBOUND_ENABLED=true`. Это реальная отправка; включайте после проверки получателей.
SMTP настраивается суперадминистратором через меню аккаунта → «Отправка email»;
до первого сохранения используются прежние настройки `.env`. См. [SMTP](SMTP.md).
ChatPush подключается одним токеном в разделе «Подключения»: сохранение не отправляет
сообщения, дополнительных scope/QR/авторизации в GateBot нет. Реальная доставка
принимается отдельно на согласованном адресате. См. [ChatPush](CHATPUSH.md) и
[подключение маркетплейса YCLIENTS](YCLIENTS_MARKETPLACE.md).

## 11. Веб-страница на телефоне

Для общения с ботом на телефоне домен или входящий порт на Windows не требуется.
Но адрес `127.0.0.1` в браузере телефона относится к самому телефону.

Для веб-страницы подключите телефон и ПК к одной локальной сети, определите IPv4
ПК командой `ipconfig` и укажите его в конфиге, например:

```dotenv
HOST=0.0.0.0
BASE_URL=http://192.168.1.50:5000
```

Замените пример на адрес своего ПК. Разрешите Python доступ в частной сети Windows
при запросе брандмауэра, перезапустите GateBot и заново скопируйте персональную
ссылку из панели. Старый адрес сервера из исходников для этого не используется.

## 12. Быстрая диагностика

| Симптом | Что проверить |
|---|---|
| `No module named ...` | Установка requirements и запуск выполняются одним `.venv\Scripts\python.exe` |
| `.env` не найден | Он рядом с `run.py`, без дополнительной вложенной папки и без расширения `.txt` |
| Изменение `.env` не действует | Перезапуск процесса; старые переменные `$env:...` в терминале/настройках запуска перекрывают файл |
| Админка не принимает пароль | Вход по `--username`, а не `--name`; `--reset-password` или восстановление из раздела 5 |
| `Expecting value` после очистки admins.json | Остановить приложение и выполнить `admin.py --recover`; обычный запуск повреждённый файл не заменяет |
| Веб работает, бот молчит | `check-bots`, затем `BOT_POLL_READY`; точный код ошибки, сеть/VPN, другой polling и старый webhook |
| CRM вернула ошибку | Сопоставление филиала и credentials; журнал; возможное истечение старых токенов |
| CRM успешна, клиентов нет | Сегодняшние подходящие записи, часы Windows и часовой пояс филиала |
| `COM` не найден или занят | Правильное устройство, драйвер USB–TTL; второй экземпляр GateBot/терминал порта остановлен |
| Открытие имитируется | `GATE_DRY_RUN=true`; для настоящего звонка нужны оба аппаратных флага из раздела 9 |

Для следующего обращения сохраните время, канал, результат `doctor`, безопасные
события и commit. Не прикладывайте `.env` или полный файл клиентских данных к
публичному GitHub issue. Команда подготовки пакета описана в [OPERATIONS.md](OPERATIONS.md).

### Работа агента прямо в Cursor

Для доступа агента к вашей локальной `.env`, Windows-сети и файлам используйте
официальное расширение **Codex от OpenAI**, идентификатор `openai.chatgpt`.
Оно поддерживает Cursor; инструкции проверены по официальным источникам 16.11.2026.

1. Откройте папку проекта в Cursor.
2. `Ctrl+Shift+X` → установите расширение OpenAI Codex.
3. `Ctrl+Shift+P` → **Codex: Open Codex Sidebar**.
4. Войдите через **Sign in with ChatGPT** и начните локальную задачу в открытой папке.
5. Попросите прочитать `AGENTS.md`, `APP_DESCRIPTION.md`, эту инструкцию и `docs/MAX.md`.

Выберите нативный Windows-режим для существующей Windows `.venv` и COM-порта.
WSL для него не обязателен. Облачный диалог сам по себе не даёт доступ к диску
вашего компьютера и не гарантирует автоматический перенос истории в новый локальный
чат. В первой задаче укажите текущую проблему и результаты диагностики.
Разрешайте читать локальные credentials для необходимых проверок, сохраняя правило:
секреты и operational data не печатать и не коммитить; YCLIENTS только чтение;
аппаратную проверку выполнять отдельным согласованным этапом.
