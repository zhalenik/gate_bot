# Уведомления клиента из таблицы

В таблице «Клиенты» колонка «Уведомления» содержит кнопку со значками фактически
включённых каналов. Неподключённый или отключённый канал не выдаётся за активный.
Если активных каналов нет, показано «Выключены». Для гостевого пропуска настройка
автоматических уведомлений недоступна.

Нажатие открывает окно настроек конкретного клиента. Изменения тумблеров
сохраняются сразу. Email, Telegram Bot и MAX Bot доступны самостоятельным
филиалам; «Мессенджеры» дополнительно доступны филиалам с YCLIENTS. Способ доставки
последнего канала выбирается в подключениях филиала. Канал «СМС» появляется при
разрешённых SMS-уведомлениях филиала. Для новых клиентов этот канал выбирается
автоматически, если недоступны мессенджеры. Отключение SMS в филиале снимает
выбор у его клиентов. Общая пауза клиентской рассылки сохраняет выбранные каналы.

## Подключение канала

- Подключённый канал включается тумблером.
- Для неподтверждённого Email администратор указывает адрес и отправляет письмо.
  Клиент подтверждает адрес по ссылке. Сохранение адреса не подменяет подтверждение.
- Для Telegram Bot / MAX Bot администратор получает ссылку и передаёт её клиенту.
  Ссылку должен открыть именно клиент в своём аккаунте; окно не открывает бот
  автоматически от лица администратора. Эта ссылка не назначает административные
  права в боте.
- После подтверждения клиентом нажмите «Проверить подключения». Возврат фокуса
  на страницу также обновляет состояние.

Отключение всех уведомлений требует подтверждения и не меняет пропуск или
персональную ссылку. Последующее включение одного канала возобновляет только его.

## Доступ

Обычный администратор управляет клиентами одного основного филиала;
суперадминистратор — всех филиалов. Scope проверяется при чтении, сохранении,
отправке подтверждения email и получении ссылки подключения бота. Клиентский
токен в запросе не расширяет административные права.

Изменение email административного профиля подчиняется прежним ограничениям:
администратор не перенаправляет чужую административную почту. Клиентские каналы
отделены от личных настроек событий администратора.

API: `/admin/api/client-notifications` (GET/POST), дополнительные POST
`/verify-email` и `/bot-link`. Все мутации требуют CSRF; ответы содержат только
данные доступного клиентского профиля.

Офлайн-проверки: `tests/test_client_notification_admin.py`,
`tests/test_client_table_controls_browser.py` и основной регрессионный сценарий
таблицы в `tests/test_ui_browser.py`.
