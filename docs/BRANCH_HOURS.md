# Время доступа по пропускам

В настройках филиала есть отдельный блок «Время доступа по пропускам». Администратор
настраивает только свой основной филиал; суперадминистратор — выбранный филиал.
По умолчанию ограничение выключено, прежние пропуска работают круглосуточно.

При включении задаются интервалы по дням недели в часовом поясе филиала:

- До четырёх интервалов в день, например 09:00–12:00 и 13:00–18:00.
- День без интервалов закрыт. «Весь день» задаёт 00:00–24:00.
- Начало включается, конец не включается: в 18:00 интервал до 18:00 уже закончен.
- Если конец раньше начала, интервал продолжается на следующий день. Воскресенье
  22:00–02:00 разрешает доступ до понедельника 02:00, даже если у понедельника нет
  собственных интервалов. Совпадающие начало и конец не допускаются.
- При переводе часов используется местное календарное время: повторяющийся час
  проверяется по тем же правилам в обоих повторениях; отсутствующее время не
  создаёт отдельного интервала. Смена часового пояса филиала меняет местное время
  оценки расписания.

Это самостоятельная проверка поверх пропуска, блокировки, состояния филиала и
подписки. Она действует и для постоянных/административных пропусков. Сохранение
расписания не меняет `gate_access`, `admin_blocked`, срок или согласие на рассылку;
ежедневных активаций и сообщений из-за смены рабочих часов нет.

При попытке открыть ворота вне расписания сервер возвращает:

> Извините, доступ возможен только в рабочие часы. Вы можете связаться с администратором.

Персональная страница показывает это сообщение сразу, включая HTML до выполнения
JavaScript. При действующем пропуске кнопки ворот остаются видимыми и выключены.
Состояние обновляется при границе интервала и периодически с сервера. Проверка
браузера не заменяет серверную: `AccessService` повторно проверяет время при приёме
команды и непосредственно перед физической попыткой из аппаратной очереди.
Команда, ожидавшая начала закрытых часов, отменяется без расхода квоты.

Постоянный QR вне расписания показывает сообщение и контакты администратора,
не запрашивает телефон и не отправляет код. Прямые запросы к API получения и
проверки кода также заблокированы. Запомненное устройство не обходит расписание,
но его привязка сохраняется и снова работает в разрешённое время.

## Реализация и проверка

В документе филиала хранится `access_schedule` с `enabled` и словарём `days`:
ключи `0`–`6` соответствуют понедельнику–воскресенью. Запись проходит через
`BranchHoursService`, действующий SQL document store и существующий контроль роли.
GET/POST `/admin/api/branches/<id>/access-hours` защищены scope и CSRF. Ошибочный
сохранённый формат закрывает доступ вместо молчаливого круглосуточного разрешения.

`tests/test_branch_hours.py`, `test_branch_hours_web.py` и `test_branch_hours_browser.py`
проверяют границы суток/недели, ночные интервалы, DST, изоляцию филиалов, очередь,
сохранность пропусков, QR без OTP, начальный HTML и мобильный редактор. Все
аппаратные и внешние эффекты подменены; рабочие данные при разработке не меняются.
