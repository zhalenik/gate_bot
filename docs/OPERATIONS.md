# Эксплуатация, журнал и поддержка

## Запуск и остановка

Используйте `python run.py`. Один процесс владеет фоновой работой и устройством. Повторный процесс с тем же каталогом данных отклоняется. Polling одного и того же токена нельзя одновременно запускать на Windows и сервере: токен — одна очередь обновлений. `app.py` и импорты модулей не являются способом запуска всей системы.

Ctrl+C прекращает приём команд, затем останавливает polling, планировщик и отправку, отменяет ожидающую очередь модема и освобождает порт. Не запускайте Flask reloader или несколько WSGI workers рядом с этим runtime.

## Что пишет журнал

`data/logs/events.jsonl`: JSON-события с `ts`, `level`, `event`, `branch_id`, псевдонимом `actor`, `correlation_id`, безопасными `details`. Ротация: до 5 MiB на файл, пять резервных файлов. Фактическая глубина истории зависит от нагрузки; срок хранения в днях пока не обещается.

Ключевые события: вход и действия администратора, выдача/отзыв прав, результат синхронизации филиала, отказ/принятие команды ворот, состояние очереди модема, отправка/ошибка уведомления, запуск и остановка runtime. Телефоны, персональные токены, пароли, cookies, authorization headers и содержимое SMS не пишутся в журнал. Бизнес-данные остаются в приватном состоянии и не копируются в support bundle.

При HTTP-ошибке сохраняйте `X-Request-ID`; при команде ворот — `command_id`. Запрос, решение доступа и физическое выполнение являются разными этапами. Отсутствие записи о физическом открытии нормально: датчика положения ворот нет.

## Диагностика

```text
python manage.py doctor
python manage.py support-bundle --output data/support-bundle.zip
python manage.py support-bundle --branch 1001 --output data/branch-support.zip
```

`doctor` описывает установленные версии, количество записей/филиалов, режимы интеграций и состояние уведомлений. Он не делает запросов в сеть и не опрашивает железо. `local_config=ok` означает локальную проверку конфигурации, а не работоспособность токена, оператора или устройства.

Support bundle содержит только `diagnostics.json`, последние маскированные события и описание состава. Даже после маскирования в нём остаются branch IDs и время событий; просмотрите файл перед передачей. Никогда не добавляйте архив bundle в публичный репозиторий.

## Диагностическая карточка проблемы

Владелец/администратор передаёт: commit/версию; дата и время с часовым поясом; branch_id; канал; ожидаемый результат; фактический текст ошибки; request/command ID; воспроизводится ли повторно; наличие изменённых настроек и версия последней рабочей сборки. Токены, пароли, полные номера и текст SMS в карточку не входят.

## Разбор типичных состояний

| Симптом | Проверить |
|---|---|
| Нет пропуска | Филиал, gate_access, admin_blocked, срок и часовой пояс, источник manual/appointment, последний успешный sync |
| В браузере есть доступ, в боте нет | Подтверждённую привязку нужной платформы; смена телефона намеренно сбрасывает связи |
| Команда принята, ворота не открылись | simulated/queued, command_id, очередь/TTL, serial/оператор. Не считать accepted подтверждением положения |
| MAX не соединяется | Актуальный hostname, наличие токена, доверенный CA bundle, активный webhook/другой poller; TLS verification не отключать |
| CRM недоступна | Наличие credentials для exact branch, HTTP-код/тип ошибки, статус полного снимка. Пустая ошибка не должна отзывать права |
| Сообщение не пришло | mailing_enabled, OUTBOUND_ENABLED, связь бота, readiness, pending/failed/unknown; состояние ChatPush |
| COM занят | Второй runtime/standalone tool, точный порт, права пользователя/группы, завершён ли прошлый процесс |
| Длинное SMS неполное | Сохранить обезличенные PDU и технические метаданные сегментов; проверить, что все части вообще присутствуют на SIM |

## Уведомления и неопределённость

Outbox сохраняет состояния pending/sending/sent/failed/unknown. В этой версии нет автоматического retry неоднозначной отправки: это предотвращает повторную рассылку после timeout. Для физической команды применяется тот же принцип — неизвестный результат не является основанием немедленно позвонить ещё раз.

Редкое окно между изменением JSON-пропуска и записью outbox остаётся до миграции на общую транзакционную БД. При сбое в это окно право может обновиться без уведомления. Авторизация проезда при этом каждый раз читает актуальное состояние.

## Резервная копия и откат

1. Остановить runtime и убедиться, что порт освобождён.
2. Скопировать весь private data directory вместе с SQLite sidecar-файлами, если они остались, и отдельно защищённый `.env`.
3. Хранить резервные копии вне публичного репозитория с ограниченными правами.
4. Восстанавливать сначала в отдельный каталог с отключёнными интеграциями и `GATE_DRY_RUN=true`.
5. Запустить doctor, проверить обе роли, число записей, токены и срок доступа.
6. Запуск реальных сервисов только после проверки; обновление кода не должно затирать `data/`.

Для контейнера применять фиксированный проверенный image tag. `pull_policy: always` обновляет образ при пересоздании/запуске согласно TrueNAS, но не является обещанием бесшовного автоматического обновления работающего процесса.
