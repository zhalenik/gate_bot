# Связь клиентов GateBot с YCLIENTS

Версия: `0.2.0-alpha.11`, 18.11.2026. Общие правила подключения и прав — [YCLIENTS.md](YCLIENTS.md), устройство очередей — [ARCHITECTURE.md](ARCHITECTURE.md).

## Что делает поиск

`YCLIENTS ID` связывает локальную карточку с клиентом CRM конкретного филиала. GateBot ищет полный нормализованный телефон только в этом филиале. Различия в записи российского номера с `+7`, `8`, пробелами или скобками не создают разных клиентов; совпадение нескольких последних цифр недостаточно.

Заполнение ID меняет только эту связь. Имя, email, привязки ботов, административная роль, персональная ссылка, пропуск, ручная блокировка и настройки уведомлений остаются прежними. Поиск не создаёт клиента в CRM и не меняет данные YCLIENTS. ID позволяет использовать рассылку через YCLIENTS, но сам по себе не включает канал и не означает согласия клиента на уведомления.

Обычный администратор работает только со своим основным филиалом. Суперадминистратор выбирает филиал. Для самостоятельных филиалов без YCLIENTS поиск недоступен.

## Автоматическое заполнение

При создании локальной карточки без ID в филиале YCLIENTS задание сохраняется в SQLite вместе с клиентом. Это общий путь записи: добавление из таблицы, регистрация администратора, консоль, бот и гостевая ссылка используют одну очередь. Создание карточки не ждёт ответа CRM.

Задания обрабатывает отдельный worker штатно запущенного приложения. Импорт модуля или открытие страницы не запускают его. Если подключение ещё не сохранено или произошла временная ошибка, автоматическое задание остаётся в очереди; повтор выполняется с интервалом от одной до пяти минут. Очередь переживает перезапуск. Если совпадений нет либо они неоднозначны, бесконечных повторов нет: после исправления данных можно обновить ID вручную.

После сохранения нового телефона прежний ID очищается и создаётся поиск для нового номера. Ответ на предыдущий номер не сможет вернуть старую связь. Простое изменение форматирования того же нормализованного телефона новым номером не считается.

Старые карточки без ID не объединяются и не удаляются автоматически. Для их проверки используйте массовое обновление.

## Обновить одну карточку

1. Откройте «Клиенты» и карточку нужного клиента.
2. Проверьте номер телефона. Если изменили его, сначала сохраните карточку.
3. Нажмите ↻ рядом с полем `YCLIENTS ID` — «Обновить ID из YCLIENTS».
4. Прочитайте результат. Единственное безопасное совпадение сохраняется сразу; при отсутствии совпадения, конфликте или ошибке прежний ID сохраняется.

Поиск использует сохранённый сервером телефон. При несохранённом изменении номера кнопка недоступна с пояснением «Сначала сохраните новый номер телефона, затем обновите ID.». Другие несохранённые поля формы результат поиска не перезаписывает.

Если карточку изменили или удалили во время запроса, ответ считается устаревшим и не записывается. Откройте актуальную карточку перед повтором.

## Обновить всех клиентов

Откройте «Интеграции» → «Связь клиентов с YCLIENTS» и нажмите «Обновить ID всех клиентов». Проверяются все локальные карточки выбранного филиала, включая уже заполненные ID и гостей. Это поиск существующих клиентов, а не импорт всей клиентской базы YCLIENTS.

Задание выполняется в фоне; страница показывает ход обработки и счётчики результатов. Можно уйти со страницы и вернуться к состоянию задания. Ошибка отдельной карточки учитывается в результате и не мешает завершить остальные. В отличие от автоматического поиска после создания клиента массовый запуск завершается также с ошибками: после устранения причины нажмите кнопку снова.

Филиал, телефон, текущий ID и права администратора проверяются перед обработкой и сохранением. Удаление клиента, смена номера или утрата доступа во время работы не позволяют записать результат в другую карточку либо филиал.

## Результаты и исправление ошибок

| Результат | Что произошло | Действие администратора |
| --- | --- | --- |
| ID получен | Найден один точный телефон, конфликта обычных карточек нет | ID уже сохранён |
| ID подтверждён | Найденный ID совпадает с сохранённым | Дополнительных действий нет |
| Клиент не найден | В доступной базе филиала нет точного телефона | Проверьте номер, филиал и наличие клиента в CRM |
| Несколько клиентов в CRM | Один полный телефон принадлежит нескольким CRM ID | Проверьте дубликаты в YCLIENTS; GateBot не выбирает первый результат |
| Конфликт локальных карточек | Другая обычная карточка филиала уже имеет этот телефон или найденный ID | Разберите дубликаты вручную; права и ссылки автоматически не переносятся |
| Подключение недоступно | Нет credentials филиала, интеграция выключена либо приложение заморожено/удалено | Проверьте «Интеграции» и системное включение YCLIENTS |
| Ошибка чтения | Недостаточно прав, ограничение запросов, неполные страницы или недоступна CRM | Проверьте подключение и права; повторите после устранения причины |
| Карточка изменилась | Ответ относится к прежнему состоянию | Откройте актуальную карточку и повторите |

Ошибки поиска не сбрасывают существующий ID. Исключение относится к отдельному действию — сохранению изменённого телефона: старая связь больше не соответствует клиенту и очищается до нового поиска.

## Планировщик и разовые гости

При обработке записи на услугу планировщик ищет обычную карточку сначала по ID CRM, затем по единственному точному телефону в том же филиале. Поэтому вручную добавленный обычный клиент без ID используется повторно, даже если отдельный фоновый поиск ещё не завершился. Сохраняются его персональная ссылка, административная роль, ручные ограничения, действующие ручные права и выбор каналов уведомлений. Административная блокировка имеет приоритет над записью на услугу.

Гостевая ссылка — отдельный разовый пропуск. Ей можно заполнить YCLIENTS ID, но это не превращает гостя в обычного клиента и не продлевает гостевой доступ по записи на услугу. Если в GateBot есть только гость, планировщик создаёт для записи отдельную обычную карточку; гостевой пропуск остаётся прежним. Это два разных разрешения, а не дубликаты обычной карточки.

Несколько обычных карточек с одним телефоном или ID считаются конфликтом. GateBot не объединяет их автоматически, не удаляет старые ссылки и не выбирает получателя наугад. Разбирать прежние дубликаты следует с учётом ролей и ручных прав; ограничения удаления последнего администратора продолжают действовать.

## Подключение, права и API

Для поиска нужны сохранённые credentials именно этого филиала — обычного пользователя либо системного пользователя Marketplace. Общие пользовательские токены из `.env` не подставляются. Пользователю YCLIENTS нужен доступ ко всей клиентской базе и полным телефонам в списке и карточке. Одних прав на журнал записей недостаточно для поиска по клиентской базе. Названия и проверяемые поля прав приведены в [YCLIENTS.md](YCLIENTS.md); настройка видимости телефонов — в [справке YCLIENTS](https://support.yclients.ru/299/).

Используется документированный `GET /api/v1/clients/{company_id}` с `phone`, `page`, `count`. YCLIENTS фильтрует телефон по подстроке; reader дополнительно сравнивает полный нормализованный номер. Проверяются все страницы, положительные ID, отсутствие повторов, согласованность количества и филиал, если он указан в ответе. Маскированные телефоны, неполные или противоречивые ответы не превращаются в успешное частичное совпадение.

В [официальной документации API](https://developers.yclients.com/ru/) этот GET помечен `Deprecated`. Современный поиск через `POST /api/v1/company/{company_id}/clients/search` не используется из-за действующего правила проекта о чтении CRM только через GET allowlist. Если старый GET станет недоступен, поиск сообщит ошибку; скрытого перехода на POST нет.

## Проверки

Reader, очередь, сопоставление, scope и интерфейс проверяются без обращения к действующей CRM, на синтетических данных и подменённых transports. Новая логика не является подтверждением работы старого GET для конкретного реального аккаунта. Зафиксированные результаты проверок и границы приёмки — [ACCEPTANCE.md](ACCEPTANCE.md).
