# Уведомления через ChatPush

Для подключения нужен только токен существующего аккаунта ChatPush. Администратор
открывает «Подключения», вставляет его в поле «Токен ChatPush» и нажимает
«Сохранить токен». Суперадминистратор сначала выбирает филиал. Дополнительные ключи,
scope, создание инстанса, сканирование QR и авторизация мессенджеров в GateBot
не требуются. Токен вводится без префикса `Bearer`.

Сохранение не выполняет запрос к ChatPush и не отправляет тестовое сообщение.
Статус «Токен сохранён» означает сохранение настройки, а не проверку доставки.
Автоматические уведомления продолжают учитывать настройки рассылки и разрешённые
каналы конкретного клиента; наличие токена само по себе их не включает. Явная
тестовая отправка доступна отдельным действием в «Интеграциях».

## Отправить тестовое сообщение

Откройте «Тестовое сообщение» в «Интеграциях» и выберите ChatPush. Введите
телефон вручную либо выберите клиента своего филиала; затем укажите текст
и нажмите «Отправить тестовое сообщение». Сообщение отправляется только после этого нажатия.
Ручной российский номер приводится к международному формату, как в других формах
GateBot. Максимальная длина текста — 3500 символов.

Форма использует сохранённый токен выбранного филиала и не меняет способ
автоматической рассылки, подписку клиента на уведомления или его пропуск.
Без токена либо при `OUTBOUND_ENABLED=false` отправка недоступна. Принятие
запроса сервисом не означает получение сообщения на устройстве; при неизвестном
исходе автоматического повтора нет. [Полные правила теста и вариант YCLIENTS](MESSENGER_DELIVERY.md).

## Выбор сервиса филиала

В разделе «Интеграции» откройте «Сервис рассылки», выберите ChatPush и введите токен. При выборе «Отключено» GateBot перестаёт использовать токен во всех каналах этого филиала. Токен остаётся зашифрованным и позволяет снова включить интеграцию без повторного ввода.

Отдельно в «Сообщения клиентам» выбирается способ маршрутизации. При автоматическом выборе используются доступные каналы для конкретного получателя. Настройка проверки телефона по QR и тестовая отправка используют активное подключение. [Маршрутизация сообщений](MESSENGER_DELIVERY.md)

## Контракт доставки

`chatpush.py` использует `POST https://api.chatpush.ru/api/v1/delivery` с JSON
ровно из двух полей: `text` и `phone`. Лимит текста — 3500 символов; если в личном
кабинете ChatPush выбран SMS-маршрут, провайдер применяет более низкий лимит.
Телефон нормализуется и передаётся цифрами
без начального плюса. Заголовок `authorization` содержит сам токен,
`content-type` — `application/json`. Проверка TLS включена, переходы по HTTP
redirect запрещены. Токен, текст и телефон не помещаются в URL или диагностические
сообщения.

Никаких запросов к `account`, WebSocket-сессий и отдельного протокола подключения
аккаунта нет. Формат `delivery.id`/`status_id` описан в
[официальной документации бизнеса](https://docs2.chatpush.ru/); заголовок с сырым
токеном соответствует проверенному владельцем запросу. Старые необязательные поля в зашифрованной настройке игнорируются;
при следующем сохранении остаётся только токен. Повторно вводить уже сохранённый
корректный токен не требуется.

Ответ с объектом `delivery` и его идентификатором означает, что провайдер принял
запрос. Это не подтверждение прочтения или фактической доставки на устройство.
При таймауте или непонятном ответе результат остаётся неопределённым, а не
выдаётся за успешную отправку. Автоматического повтора такого запроса нет:
документированный ключ идемпотентности в этом контракте не используется.

## Хранение и доступ

Токен хранится зашифрованным в `identity_integrations` базы `application.sqlite3`.
Ключ `integration.key` и БД нужно резервировать согласованно. API возвращает
только признак настройки, а поле токена очищается после сохранения. Администратор
может менять настройки только своего основного филиала; суперадминистратор —
любого. Существующее ограничение продукта сохранено: ChatPush доступен филиалам
с `yclients_enabled=true`.

Глобальный `OUTBOUND_ENABLED=false` блокирует отправку, даже если токен сохранён.
Токен не следует добавлять в Git, публичные логи, скриншоты или документацию.

## Проверки

`tests/test_chatpush_delivery.py` проверяет точный адрес, сырой заголовок
авторизации, состав JSON, нормализацию телефона, TLS, обработку отказов и
неопределённых результатов. `tests/test_integration_connections.py` проверяет
сохранение одного токена, шифрование, изоляцию филиалов и совместимость старых
сохранённых настроек. `tests/test_integrations_browser.py` проверяет форму в
браузере. Все проверки используют синтетические токены и подменённую сеть;
реальных отправок нет.
