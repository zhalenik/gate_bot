# Подключение GateBot через маркетплейс YCLIENTS

Проверено по официальным материалам 18.11.2026. Код и тесты подготовлены; реальная
активация в действующей CRM, настройка карточки приложения и модерация не выполнялись.

## Как работает подключение

YCLIENTS направляет пользователя на Registration redirect URL с `salon_id`.
После регистрации **или входа существующего пользователя** GateBot должен завершить
подключение за один час. При установке в филиал добавляется системный пользователь
приложения с выбранными правами. Это отдельная операция установки, а не обычное
чтение записей CRM. [Официальный сценарий подключения](https://support.yclients.ru/67-68-191).

В GateBot реализовано:

1. `/yclients/marketplace/connect` принимает переход, сохраняет ограниченное по
   времени намерение подключения в SQLite и убирает параметры из адресной строки.
2. Посетитель входит в существующий аккаунт или регистрирует новый филиал с SMS-кодом.
   Контекст подключения сохраняется при входе. При регистрации ID филиала не вводится:
   сервер берёт его из сохранённого перехода; изменить его в запросе нельзя.
   Посетитель указывает название, своё имя, телефон, email и пароль GateBot.
3. На странице подключения показаны выбранные филиалы. Действие выполняется только
   для филиала, на который у аккаунта есть актуальные административные права.
4. «Подключить» делает один запрос установки. Повторное нажатие не повторяет эффект.
   После таймаута используйте «Проверить состояние»: выполняется GET, не повторный POST.
5. После подтверждённой установки сохраняются зашифрованные credentials филиала для
   существующего GET-only CRM reader. Пароль пользователя YCLIENTS не нужен.
6. В «Интеграциях» показывается карточка «Приложение YCLIENTS Marketplace» со статусом
   и проверкой связи. Форма «Учётная запись YCLIENTS» отсутствует, ручная авторизация
   запрещена и на сервере — в том числе до завершения установки и после отключения.

Это второй способ подключения. Первый — регистрация с ID филиала и вход обычного
пользователя в карточке «Учётная запись YCLIENTS», без установки приложения.
Оба сценария описаны в [YCLIENTS.md](YCLIENTS.md); тип подключения сохраняется у филиала.

Новый филиал после OTP остаётся на проверке суперадминистратором GateBot. После
проверки нужно **ещё раз начать подключение из карточки YCLIENTS**, чтобы получить
свежий час на установку. Это защищает от присвоения чужого филиала: число `salon_id`
в URL не доказывает права. Смена этой процедуры требует отдельного подтверждённого
контракта проверки владельца филиала.

## Что заполнить в кабинете разработчика

Создайте приложение GateBot в кабинете разработчика, заполните карточку и описание
работы с парковкой. Процесс создания и чек-лист публикации описаны в
[пошаговом гайде](https://support.yclients.ru/67-68-189--poshagovyj-gajd-po-razmesheniyu-v-marketplejse/).

Подставьте свой публичный HTTPS-домен вместо `gatebot.example`:

| Поле/настройка | Значение |
|---|---|
| Registration redirect URL | `https://gatebot.example/yclients/marketplace/connect` |
| Адрес кабинета/настроек приложения | `https://gatebot.example/admin/integrations` |
| Webhook событий отключения приложения | `https://gatebot.example/webhook/yclients/marketplace` |
| Открывать регистрацию в iframe | Выключить: эта сборка использует самостоятельную страницу и `X-Frame-Options: DENY` |
| Передавать данные пользователя | Можно включить: подпись проверяется, данные только заполняют форму |
| Подключение нескольких филиалов | Поддержано для уже зарегистрированных и доступных аккаунту филиалов; новые филиалы регистрируются и проверяются отдельно |

В разделе доступа к API YCLIENTS автоматически создаёт системного пользователя и
показывает его **User token**. Выберите необходимые права чтения журнала,
записей, клиентских контактных данных и сотрудников. Если филиал выбирает уведомления
через YCLIENTS, дополнительно нужны права на рассылку; для ChatPush напрямую эти права
не нужны. Создание/редактирование записей, финансы и управление правами пользователей
GateBot не использует. [Доставка уведомлений](MESSENGER_DELIVERY.md).
Ключ партнёра берётся из настроек аккаунта разработчика; он отличается от User token.
[Доступ к API и системный пользователь](https://support.yclients.ru/67-68-199--dostup-k-api/).

## Настройки установки GateBot

Начальные значения задаются приватно в `.env`; суперадминистратор также может менять
их в системных настройках. Сохранённые секреты не возвращаются браузеру:

```dotenv
BASE_URL=https://gatebot.example
SESSION_COOKIE_SECURE=true
YC_PARTNER_TOKEN=
YC_MARKETPLACE_APPLICATION_ID=
YC_MARKETPLACE_SYSTEM_USER_TOKEN=
YC_MARKETPLACE_CONNECT_ENABLED=false
```

`YC_MARKETPLACE_APPLICATION_ID` — числовой ID созданного приложения.
`YC_MARKETPLACE_SYSTEM_USER_TOKEN` — User token именно системного пользователя этого
приложения, не токен случайного администратора одного филиала. Callback установки
не возвращает новый пользовательский токен: после установки применяется заранее
настроенный системный токен.

Этот системный токен может быть общим для установок приложения: отдельность филиалов
обеспечивается сохранённым подключением и проверкой установки/прав, а не различием
строк токенов. Обычные `YC_USER_TOKEN` и `YC_USER_TOKEN_<branch_id>` из окружения не
используются. Для ручного сценария нужен токен, полученный и сохранённый именно при
подключении соответствующего филиала.

Флаг установки оставлен выключенным: действующие инструкции проекта запрещают нам
менять рабочую CRM. Когда владелец отдельно разрешит активацию на выбранном стенде,
оператор включает `YC_MARKETPLACE_CONNECT_ENABLED=true` и перезапускает `run.py`.
Это разрешает только явное действие «Подключить»; обычный CRM reader остаётся GET-only.
`YCLIENTS_ENABLED=true` и `SCHEDULER_ENABLED=true` включают дальнейшее чтение расписания.

Для проверки внешнего сценария нужны HTTPS-домен и доступный callback. `localhost`
подходит для офлайн-проверки форм, но не для входящего серверного webhook YCLIENTS.
В текущем сеансе реальные ключи и флаги подключения в `.env` не менялись.

## Контракт и ограничения

Установка: `POST https://api.yclients.ru/marketplace/partner/callback`, заголовок
`Authorization: Bearer <partner token>`, JSON с числовыми `salon_id` и `application_id`;
успех — HTTP 201. Поля `webhook_urls`, `api_key`, `channels` не передаются: GateBot не
регистрирует SMS-агрегатор и не меняет webhook записей бизнеса.

Сверка: `GET /marketplace/salon/{salon_id}/application/{application_id}`. Входящий
lifecycle webhook содержит `salon_id`, `application_id`, `event` и `partner_token`.
Токен сравнивается константным по времени способом, ID приложения проверяется.
`uninstall`/`freeze` останавливают локальное чтение CRM; ручные пропуска, роли и
подписка GateBot сохраняются. Отключённое подключение не обходится fallback-токеном
из `.env`. [Контракты marketplace API](https://developers.yclients.ru/ru/).

Текущее состояние отключения имеет приоритет над результатом старой попытки
установки. Поздний повтор callback нельзя отличить от нового отключения: контракт
не содержит ID события или времени. GateBot безопасно приостанавливает чтение;
«Проверить состояние» подтверждает текущий статус GET-запросом и восстанавливает
подключение только при ответе `active`. Callback сам не отправляет сетевые запросы.

При включённой передаче пользователя GateBot проверяет HMAC-SHA256 **исходных байтов
декодированного JSON** `user_data` с ключом партнёра и `user_data_sign`. Подпись не
покрывает отдельные query-параметры филиалов, поэтому не выдаёт права и не отменяет
SMS-проверку. Профиль в ожидании хранится зашифрованно; сырые параметры и webhook
нельзя включать в proxy/access logs. [Передача данных пользователя](https://support.yclients.ru/67-69-212).

Массив `salon_ids[]` разбирается отдельно; неоднозначное сочетание с `salon_id`
отклоняется. Каждый филиал проходит самостоятельную проверку прав и установку.
[Несколько филиалов](https://support.yclients.ru/67-69-215).

Для публикации YCLIENTS проверяет также оплату/возвраты и отключение/повторное
подключение. Реальный эквайринг в GateBot ещё заглушка: фиктивные платежи и возвраты
не отправляются. Поэтому готовность этого connection flow не означает завершённую
модерацию платного приложения. [Требования модерации](https://support.yclients.ru/67-68-207--moderaciya-prilozheniya/).

## Проверки в репозитории

`tests/test_yclients_marketplace.py`: точный wire contract, TLS, выключенная установка,
HMAC и изменённая подпись, истечение часа, другой браузер, несколько филиалов/scope,
pending verification, повтор/таймаут/сверка GET, callback с чужим ключом, гонка
отключения с установкой, сохранность ручных прав и блокировка CRM fallback.
`test_yclients_modes.py` и `test_integrations_browser.py` проверяют регистрацию без
ручного ID, сохранение режима, скрытие и серверный запрет обычной авторизации,
истечение контекста и замену чужого ID в запросе.
Все внешние эффекты подменены; реальная CRM не вызывалась.
