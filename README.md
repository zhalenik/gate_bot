# GateBot

Управление доступом на парковку для нескольких филиалов: веб-интерфейс, Telegram и MAX, записи YCLIENTS и GSM-модуль SIM800C.

**Текущая версия: `0.1.0-alpha.1`, сборка для локальной приёмки.** Восстановлена из двух исходных архивов; исправлены границы доступа, добавлен MAX, реализованы драйвер SIM800C и чтение составных SMS. Проверяется офлайн и в CI. Реальные боты, действующая CRM, модем и контейнер на TrueNAS требуют отдельной приёмки. По умолчанию реальные интеграции отключены.

## Быстрый запуск на Windows

Нужен Python 3.12 или 3.13. Команды выполняются в PowerShell в каталоге репозитория.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe manage.py init-demo
.\.venv\Scripts\python.exe admin.py --username owner --name "Суперадминистратор" --super
.\.venv\Scripts\python.exe run.py
```

Пароль администратора вводится в терминале; он не появляется в команде или исходниках. Интерфейс: `http://127.0.0.1:5000/admin/login`. Команда `init-demo` выводит персональную ссылку демонстрационного клиента. Демо использует вымышленные номера и `GATE_DRY_RUN=true`.

Не выполняйте `Copy-Item` поверх уже заполненного `.env`. Для проверки реальных ботов добавьте их токены локально и включайте по одному согласно [инструкции](docs/WINDOWS.md).

## Основные ограничения и гарантии

- YCLIENTS: только разрешённые `GET`; записи, клиенты, настройки CRM и SMS через CRM не изменяются.
- Филиал — граница доступа. Обычный администратор управляет только своим филиалом. Одинаковый `client_id` в разных филиалах не объединяется.
- Веб, Telegram и MAX проверяют один общий `AccessService`. Номер ворот не принимается от клиента.
- Подтверждение телефона: собственный контакт Telegram; подписанный контакт MAX; либо персональная ссылка. Ручной ввод номера не является авторизацией.
- Ответ о принятии команды не доказывает физическое открытие: датчика положения ворот в проекте нет.
- Один процесс `run.py` владеет планировщиком, polling и COM-портом. Горизонтальное масштабирование этой сборки не поддерживается.
- ChatPush, регистрация через маркетплейс и CRM webhooks в исходниках не были реализованы. Они явно помечены как недоступные; работа через периодическое чтение CRM реализована.
- Подписки, биллинг, EXOLVE и автоматический импорт сотрудников остаются отдельными будущими этапами.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/scan_public_tree.py
.\.venv\Scripts\python.exe manage.py doctor
```

Тесты используют отдельное временное состояние и запрещают сетевые соединения. CI запускает их на Windows и Linux с Python 3.12/3.13. `doctor` не делает запросов к сервисам и не обращается к модему.

## Данные и секреты

`.env`, `data/`, журналы, базы очередей, номера ворот и учётные данные не публикуются. В репозитории есть только вымышленные примеры. Изменения исходных архивов не импортируются в существующую CRM и не заменяют рабочие данные автоматически. Старые TODO сохранены в `docs/archive/` как история замысла, а действующий план находится в `docs/ROADMAP.md`.
